# map-vectorize

Автоматическая **векторизация растровых тематических карт** в GeoJSON: из скана карты —
полигоны **всех единиц легенды** (площадные; со временем — линии/точки), привязанные к
географическим координатам. Без ручного снятия точек, локально, только open-source.

Пилот и первый вход — **карты четвертичных отложений ГГК-1000/3** (1:1 000 000, ВСЕГЕИ,
3-е поколение) на Ленинградскую область: листы `P-(35),36` (север, 60–64°N) и
`O-35,N-35,O-36` (юг, 56–60°N). Геопривязка — **сменный модуль** под тип карты (сейчас —
номенклатура IMW/ГГК); сама векторизация картонезависима.

Проект `../mushrooms` (фильтрует песчаные единицы `f`/`v`/`lg` под боровые местообитания) —
**один из потребителей** результата, а не цель.

> **Главный предел точности:** «цвет ≠ генетический индекс». Сегментация относит пиксель к
> ближайшей по цвету единице; единицы разного цвета разделяются, одного цвета/разного
> индекса (`fIII` vs `fII`) — нет. Это приближённая оцифровка, не геодезическая: результат —
> **приоритеты для разведки**, не гарантия. Детали — в `.claude/rules/pipeline.md`.

## Требования

- **Python 3.12** (проверено; через `pyenv`).
- `pip install -r requirements.txt` — rasterio, numpy, Pillow, shapely, scikit-image,
  scipy, pytesseract.
- **Системный Tesseract 5.x** с языковыми пакетами **`rus` + `eng`** (OCR подписей градусов
  при привязке и индексов легенды). Проверить: `tesseract --list-langs`.
- `gdal`/`osgeo` **не нужны** — хватает `rasterio`.

```bash
pip install -r requirements.txt
tesseract --list-langs          # должны быть eng и rus
```

## Быстрый старт

```bash
python src/fetch_sources.py           # 1. скачать исходники в data/raw/ (geokniga)
python src/vectorize.py P-35-36       # 2. весь лист → output/P-35-36_all.geojson
```

`vectorize` сам прогоняет привязку и извлечение легенды — для чистого результата одной
команды достаточно. Второй шаг повторить для `O-35-36`.

## Конвейер и команды

Запускать из корня репозитория. `<key>` — ключ листа из словаря `SHEETS` в
`src/georef.py` (`P-35-36`, `O-35-36`), **не** номенклатурный `sheet_id`.

| Команда | Что делает | Результат |
|---|---|---|
| `python src/fetch_sources.py` | скачать растры + PDF легенд | `data/raw/` |
| `python src/georef.py <key>` | ② авто-привязка (номенклатура + сетка → EPSG:4326) | `data/work/<key>_georef_4326.tif` |
| `python src/legend.py <raw.jpg>` | ③ авто-палитра легенды (свотчи + OCR индексов) | печатает `{генезис: [RGB]}` |
| `python src/vectorize.py <key>` | ④–⑤ **все** единицы легенды | `output/<key>_all.geojson` |
| `python src/vectorize.py <key> f,lg` | ④–⑤ подмножество генезисов | `output/<key>_f_lg.geojson` |

- Отдельно `georef` / `legend` гоняют для отладки и чтения **ворот доверия** (логи `[C/…] rms`,
  `[fuse] …`, доля `?` в легенде) — см. навык `.claude/skills/vectorize-map/`.
- Второй аргумент `vectorize`: `all`/пусто — все единицы; иначе генезисы через запятую
  (`f`, `v`, `lg`) — срез для потребителя mushrooms.

## Результат (GeoJSON)

`output/<key>_<tag>.geojson` — `FeatureCollection`, **EPSG:4326 (CRS84)**, координаты
округлены до 5 знаков (~1 м). Атрибуты фичи:

| Поле | Значение |
|---|---|
| `unit` | генезис (`f`, `lg`, `g`, …) или `?` при провале OCR генезиса |
| `label` | id класса (`f`; для неизвестных — `?1`, `?2`, … раздельно по цвету) |
| `index` | сырой OCR-текст индекса из легенды (best-effort) |
| `rating` | ★ боровика (линза потребителя mushrooms; на векторизацию не влияет) |
| `color` | `r,g,b` центроида свотча |

Потребитель `../mushrooms` фильтрует `_all` по `unit ∈ {f, v, lg}` (или берёт готовый
`_f_lg`). `output/*.geojson` — **в git** (самодостаточно); `data/raw/` и `data/work/` —
**не в git** (воспроизводятся).

## Добавить новый лист

1. Положить растр в `data/raw/` (или прописать URL в `src/fetch_sources.py`).
2. Добавить запись в `SHEETS` (`src/georef.py`):
   ```python
   "<key>": dict(raw="data/raw/<файл>.jpg", sheet_id="<номенклатура IMW>"),
   ```
   `sheet_id` (напр. `P-(35),36`, `O-35,N-35,O-36`) — из него `src/nomenclature.py`
   детерминированно выводит градусную рамку (ряд = 4° широты, колонна = 6° долготы;
   составные/сдвоенные листы поддержаны).
3. `python src/vectorize.py <key>` и проверить ворота.

Константы подобраны на двух листах ГГК-1000. На другой серии/масштабе (например ГГК-200,
проекция Гаусса-Крюгера) ожидаемо нужна подстройка — привязка задумана сменным модулем.

## Структура и документация

```
src/            конвейер: fetch_sources, nomenclature, georef, legend, vectorize
data/raw/       исходные растры + PDF легенд (не в git)
data/work/      привязанные GeoTIFF, промежуточное, вьюер (не в git)
output/         результат — GeoJSON (в git)
.claude/rules/  архитектура и решения
```

- `.claude/rules/pipeline.md` — архитектура конвейера (привязка, легенда, сегментация,
  ворота доверия, осознанные ограничения).
- `.claude/rules/legend.md` — единицы легенды и атрибуция.
- `.claude/rules/sources.md` — источники, URL, доступ к .ru-ресурсам.
- `.claude/skills/vectorize-map/` — операционный сценарий (порядок стадий, чтение ворот,
  ручной фолбэк) для работы через Claude Code.
