# Векторизация листа карты → GeoJSON

Операционный сценарий конвейера этого репозитория: растровый лист тематической карты →
GeoJSON площадных единиц легенды (EPSG:4326). Архитектура и обоснования — в
`.claude/rules/pipeline.md`; единицы и атрибуция — в `.claude/rules/legend.md`; источники
и доступ к .ru — в `.claude/rules/sources.md`. Этот файл **не дублирует** правила, а
говорит, что и в каком порядке запускать и как читать результат.

## Когда применять

- Оцифровать новый лист (есть растр `*.jpg` в `data/raw/`).
- Перезапустить/разобрать стадию `georef`, `legend` или `vectorize`.
- Истолковать логи стадий и ворота доверия, решить про ручной фолбэк.

## Предпосылки (окружение)

- Python 3.12 (здесь — через `pyenv`, `python` в PATH). Отдельного `venv` в репозитории нет.
- `pip install -r requirements.txt` (rasterio, numpy, Pillow, shapely, scikit-image;
  scipy подтянется транзитивно со scikit-image).
- **OCR:** `pytesseract` (Python) + системный `tesseract` 5.x с языковыми пакетами
  **`rus`+`eng`** — его используют `georef.py` (подписи градусов) и `legend.py` (индексы
  свотчей). `pytesseract` в `requirements.txt` сейчас **не объявлен** — поставить вручную
  (`pip install pytesseract`), пока не добавлен в зависимости.
- `gdal`/`osgeo` не нужны — `rasterio` достаточно.
- Исходные растры тянутся `python src/fetch_sources.py` (geokniga — мимо тоннеля,
  см. `sources.md`). `data/raw/` и `data/work/` — **не в git**; `output/*.geojson` — **в git**.

## Конвейер по стадиям

Ключ листа (`<key>`) — это ключ словаря `SHEETS` в `src/georef.py` (например `P-35-36`),
**не** номенклатурный `sheet_id`. Запускать из корня репозитория.

```bash
python src/fetch_sources.py                 # (один раз) скачать исходники → data/raw/
python src/georef.py <key>                  # ② привязка → data/work/<key>_georef_4326.tif
python src/legend.py data/raw/<raw>.jpg      # ③ палитра легенды (печатает {генезис:[RGB]})
python src/vectorize.py <key>                # ④–⑤ ВСЕ единицы легенды → output/<key>_all.geojson
python src/vectorize.py <key> f,lg           #     подмножество генезисов → output/<key>_f_lg.geojson
```

- `vectorize.py` сам вызывает `georef(..., resampling=nearest, out_suffix="_seg")` и
  `legend.extract(raw)` — для чистого прогона достаточно последней команды. Отдельно
  `georef`/`legend` гоняют для отладки и чтения ворот.
- Второй аргумент `vectorize`: `all` (или пусто) — **все единицы легенды**
  (`output/<key>_all.geojson`); иначе генезисы через запятую (`f`, `v`, `lg`) —
  подмножество (`output/<key>_<gen_gen>.geojson`, срез для потребителя mushrooms).
- **Модель класса — свотч легенды, не генезис** (`build_classes`): оттенки одного
  распознанного генезиса группируются (`unit=f`), а свотчи с провалом OCR генезиса
  держатся раздельно по цвету (`unit=?`, `label=?N`) — не схлопывать разноцветные
  неизвестные единицы. Атрибуты фичи: `unit` (генезис), `label` (id класса),
  `index` (сырой OCR-текст, best-effort), `rating` (★ боровика), `color` (`r,g,b`).
- Координаты округлены до 5 знаков (~1 м): привязка км-точна, больше знаков — ложная
  точность. Потребитель mushrooms фильтрует `_all` по `unit ∈ {f,v,lg}` (или берёт
  готовый `_f_lg`).

## Как добавить новый лист

1. Положить растр в `data/raw/` (или прописать URL в `src/fetch_sources.py`).
2. Добавить запись в `SHEETS` (`src/georef.py:27`):
   ```python
   "<key>": dict(raw="data/raw/<файл>.jpg", sheet_id="<номенклатура>"),
   ```
   `sheet_id` — обозначение листа IMW (`P-(35),36`, `O-35,N-35,O-36`): движок
   `src/nomenclature.py` детерминированно выводит из него градусную рамку (ряд=4° широты,
   колонна=6° долготы; составные/сдвоенные листы поддержаны).
3. Прогнать `georef` → `vectorize`, проверить ворота (ниже).

Константы подобраны на двух листах ГГК-1000 (Балтийская и Центрально-Европейская серии).
На другой серии/масштабе (например ГГК-200, проекция Гаусса-Крюгера) ожидаемо потребуется
подстройка — геопривязка задумана как **сменный модуль**.

## Ворота доверия (что проверять)

Скор доверия ≠ истина — ворота это фильтр внимания, не гарантия (см. `pipeline.md`).

| Стадия | Сигнал в логе | Норма (наблюдалось на 2 листах) | Разошлось → |
|---|---|---|---|
| ② georef | `[C/top] … rms=…deg`, `[C/bot] …` | rms 0.00–0.01° | ручной фолбэк привязки |
| ② georef | `[fuse] … меридианы …E (номенклатура …)` | экстент C согласован с рамкой A | проверить OCR подписей / номенклатуру |
| ② georef | валидация по озёрам Natural Earth | внутр. озёра 0.6–4.9 км; края (клип/экстраполяция) 11–17 км | большой offset → фолбэк |
| ③ legend | число свотчей и генезисы `{f,lg,g,…}` | целевые `f`/`lg` присутствуют с RGB | мало свотчей / нет цели → ручная палитра на серию |
| ③ legend | доля `?` среди свотчей (провал OCR генезиса) | низкая (P ~⅟₁₅) | высокая (O ~⅓ → в `_all` ~½ полигонов `unit=?`) → слабый OCR, ручная доатрибуция/правка regex |
| ④–⑤ vectorize | `[label gen] RGB=… маска …px -> M полигонов` + `[key] классов N из M` + `ИТОГО` | ненулевые разумные площади; целевые единицы не пустые | 0 полигонов или абсурдная площадь → проверить палитру/допуск |

Главный риск — **OCR кириллических индексов** в легенде: `legend.classify` берёт только
первую букву генезиса (устойчивее точного кода), но при сбое падает в `?` (единица не
теряется — держится по цвету с `label=?N` и сырым `index`, но без генезиса). Высокая доля
`?` = сигнал слабого OCR легенды на этой серии.

## Ручной фолбэк — когда

- Сигналы A↔B↔C не сходятся, либо `[C]` rms высокий / RANSAC не нашёл шкалу.
- Валидация по озёрам даёт большой offset (на безводном листе — доверять D осторожно,
  это только верификация, не источник GCP).
- Легенда не распозналась: завести **ручную таблицу `{индекс→RGB}` на серию** и передать
  её палитрой в сегментацию.

Помеченный на ручную проверку лист/единица **не уходит в результат как факт** — пересечь
с реальностью (сосняк, точки почв) у потребителя.

## Результат и потребитель

- `output/<key>_<genera>.geojson` (EPSG:4326, CRS84), атрибуты: `unit` (генезис),
  `rating` (★ боровика для линзы потребителя).
- Потребитель — вьюер `../mushrooms` (слой приоритетов разведки). Рейтинг боровика —
  линза именно этого потребителя, на саму векторизацию не влияет (см. `legend.md`).

## Осознанные ограничения

Это **приближённая** оцифровка, не геодезическая: предел точности — «цвет ≠ генетический
индекс» (единицы одного цвета, но разного индекса не разделяются без OCR индексов на теле
карты). Цифры точности из литературы на советские 1:1М поликонические кириллические листы
количественно не переносятся. Результат — **приоритеты для разведки**, не гарантия.
