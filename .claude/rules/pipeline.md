# Конвейер оцифровки (архитектура)

Цель — **сквозной АВТОМАТИЧЕСКИЙ конвейер** универсальной векторизации: растровая
тематическая карта → GeoJSON полигонов **ВСЕХ единиц легенды с максимальной точностью**,
**без ручного снятия точек**. Векторизация картонезависима; привязка — сменный модуль под
тип карты (сейчас — номенклатура IMW/ГГК). Пилот — ЛО (P-(35),36, O-35,36). Пески для
`../mushrooms` — один из потребителей, фильтрует нужные единицы, не цель.
Инструменты — `rasterio`, `numpy`, `scikit-image`, `shapely`, `opencv`, `pytesseract`
(чистый Python; `gdalwarp`/`osgeo.gdal` в среде НЕТ, rasterio достаточно). Только
open-source, локально, без облачных API.

**Главный предел точности — «цвет ≠ генетический индекс».** Сегментация относит пиксель к
ближайшей по Lab единице; единицы РАЗНОГО цвета разделяются, одного цвета/разного индекса
(`fIII` vs `fII`) — нет. Максимальная точность атрибуции требует **OCR индексов на теле
карты** (как TOPAZ/CriticalMAAS, но там на GPT-4o; открытого локального решения для
кириллицы нет — это главный нерешённый фронт).

Обоснование решений и первоисточники — в `docs/`:
`research-existing-solutions.md`, `research-auto-georeferencing.md`,
`research-critique-decisions.md`. Единицы и цвета — в `legend.md`.

## Главный принцип: авто + ворота доверия + ручной фолбэк

Полная автоматизация **недостижима** (лит.: даже лучший аналог MapEdge ~1.6% листов
вручную; для кириллических перегруженных ГГК — выше). Поэтому каждая стадия имеет
**ворота качества**; лист/единица с низкой уверенностью **помечается на ручную
проверку**, а не уходит в результат как факт. **Скор доверия ≠ истина** (авто-верификация
правильности — классическая нерешённая проблема): ворота — фильтр внимания, не гарантия.

## Стадии

```
raw CMYK скан
 ① Preprocess ─ CMYK→RGB; descreening (median); автодетекция рамки (neatline)
 ② Georef ──── слияние сигналов → узловые GCP → warp     ⟂ ворота: согласие + offset
 ③ Legend ──── свотчи (RGB) + OCR индексов → {индекс→RGB, рейтинг}  ⟂ ворота (риск!)
 ④ Segment ─── маска Lab/HSV + морфология + пространственный слой
 ⑤ Polygonize ─ features.shapes → shapely → GeoJSON (EPSG:4326)
 ⑥ QA ──────── сводка + флаги на ручную проверку
```

### ① Preprocess
Лист = карта + панель легенды (справа) + разрезы (внизу) + заголовок. Нужна только
**область внутри рамки (neatline)**.
- Скан в **CMYK** → конвертировать в RGB.
- **Descreening ОБЯЗАТЕЛЕН** (Chiang 2014): полутоновая CMYK-печать даёт точечную/муаровую
  текстуру, рвущую цвет-маски. Медианный фильтр (или mean-shift) ДО любой сегментации.
- **Автодетекция рамки (устойчиво к раскладке):** сид полос — по **bbox цветного тела
  карты** (насыщенная заливка геологии отличает карту от полей/легенды/разрезов), НЕ по
  фиксированным долям высоты. В полосах у верх/низ кромок — оконное голосование по
  строкам + робастная подгонка окружностей (дуги параллелей). Проверено на обоих листах:
  rms 0.4–0.6 px.

### ② Georef — слияние сигналов (проекционно-агностично)
Проекция 1:1М — **видоизменённая поликоническая**: меридианы прямые, но **НЕ сходятся
в один полюс**; параллели — **дуги окружностей**; рамка трапециевидная. (Для ГГК-200 —
Гаусса-Крюгера.) Аналитическое восстановление проекции **хрупко** (нужно ~10 точек,
вырождается на конике/малых охватах, невыпукло) — **не восстанавливаем проекцию**,
работаем по точкам.

Четыре независимых сигнала:
- **A — OCR номенклатуры → углы (IMW).** Движок разграфки (`src/nomenclature.py`): ряд=4°
  широты, колонна=6° долготы, двойные листы 12° в поясе 60–76°N. Широта — по
  **доминирующему ряду** (устойчиво к составным ID вроде `O-35,N-35,O-36`, где лишний ряд —
  артефакт). Углы выводятся **детерминированно**. OCR заголовка: Tesseract → PaddleOCR/docTR
  при провале ворот.
- **B — детекция рамки/сетки → узловые GCP (ОСНОВА).** ≥10 хорошо распределённых узлов
  (целимся ~50). Снимает зависимость от матчасти проекции.
- **C — OCR подписей градусов у рамки** → присвоение долготы дугам (ловит клип, напр.
  запад по госгранице). Лента **ректифицируется вдоль дуги** + **grayscale** (Tesseract-Otsu;
  жёсткий порог рвёт подписи) + положение ленты **зависит от стороны** (верх — подписи под
  линией, низ — над внешней рамкой) + RANSAC-фит lon↔угол. Оба листа: rms 0.00–0.01°.
- **D — гидрография ↔ опора (OSM/Natural Earth) — ТОЛЬКО ВЕРИФИКАЦИЯ.** НЕ источник GCP.
  Кросс-модальный SuperGlue не использовать (доказан лишь карта↔карта одного стиля).
  Деградирует на безводных листах (>1000 м) и даёт **ложно-высокий** скор (локальные
  минимумы) — доверять осторожно.

**Фьюжн:** `USAC_MAGSAC` (НЕ дефолтный `cv2.RANSAC`) + слой геометрической
согласованности (Delaunay) + защита от вырожденных (bow-tie) выборок. Для чистых узловых
корреспонденций RANSAC — лёгкий страж. `rasterio` + `GroundControlPoint` →
`rasterio.warp.reproject` (полином 2-го порядка/TPS) в EPSG:3857. Привязанный GeoTIFF —
`data/work/` (gitignore).

**Ворота:** согласие A↔B↔C (углы в px) + residual GCP-подгонки + offset по D (если вода
есть). Разошлось → **ручной фолбэк**.

### ③ Legend — автоизвлечение (ЗОНА РИСКА)
Детекция цветовых свотчей (чистые прямоугольники — RGB снимается легко) + OCR индекса
рядом (`fIII`, `lgIIIos`…) → таблица `{индекс → RGB, рейтинг боровика}` (рейтинг — из
`legend.md`). **OCR кириллических индексов — главный риск** (в литературе данных нет).
Ворота: доля распознанных свотчей, regex-валидация индексов; иначе — ручная таблица на
серию (2 серии: север — Балтийская, юг — Центрально-Европейская).

### ④ Segment — цвет → маска
Решение: **сегментация ТОЛЬКО по цвету** (принимаем «цвет ≠ индекс»; OCR индексов на
теле карты — потом, опция). У цвет-онли есть потолок (не моделирует связность) → нужен
**пространственный слой**.
1. Маска по каждому целевому цвету с допуском (Lab/HSV устойчивее RGB).
2. **Оверпринт** (подписи, границы, сетка, реки, скважины, малиновые пунктиры озов) рвёт
   маску: морфология `closing` (закрыть разрывы от подписей) + `opening`/
   `remove_small_objects` (убрать мусор); при нужде суперпиксели (SLIC)/CRF для связности.

### ⑤ Polygonize
`rasterio.features.shapes(mask, transform=...)` → полигоны сразу в геокоординатах →
`shapely`: `simplify`, фильтр по площади → GeoJSON (EPSG:4326) с атрибутом единицы и
рейтингом. **Озы/эскеры** (малиновые пунктиры) — отдельный слой линий, не терять как мусор.

### ⑥ QA
Сводка: кол-во/площадь полигонов, offset привязки, флаги на ручную проверку.

## Осознанные ограничения (без иллюзий)
- Это **приближённая** оцифровка, не геодезическая. Результат — **приоритеты для
  разведки**, не гарантия; сверять с сосняком и точками почв в mushrooms.
- Цифры точности из литературы (RMSE, % ручных) **не переносятся** на ГГК количественно —
  ни один источник не тестировал советские 1:1М поликонические кириллические геокарты.
- Главные неизвестные (прототип + замер, не закладываться): OCR кириллических индексов/
  номенклатуры; выигрыш DL/SAM над descreened цвет-онли; кросс-модальная альтернатива D.
